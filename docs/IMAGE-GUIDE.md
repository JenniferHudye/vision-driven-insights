# Image Guide

## Hero images (automatic, every article)

Every article gets a branded SVG hero image automatically, generated by `scripts/refresh-hero-images.cjs` and written to `public/articles/hero/<slug>.svg`. This is the primary image source, not a fallback. You never have to source an image for an article to go live.

To swap in a real photo instead: save the file to `public/assets/`, then set that article's `featuredImage.src` in `data/blog/posts.json` (or `queue.json`) to the new path, and its `featuredImage.alt` to a real description. Run `npm run build` again.

## Naming

`[article-slug]-hero.webp` for a real photo, or the auto-generated `<slug>.svg` for the default hero. In-article images follow the same slug-based naming.

## Alt text

Every image needs alt text that describes the image AND naturally includes the article's primary keyword where it fits. `scripts/check-image-tags.cjs` fails the build if alt text is missing or too short.

## Sourcing rule (hard rule, see `IMAGE-SOURCING-RULE.md`)

Only: images Jennifer owns, Unsplash/Pexels/Pixabay (screened for faces, logos, and brands), or AI-generated images from a free tier that grants commercial rights (Google Gemini/Imagen, ChatGPT image, Adobe Firefly). Never Google Images, Pinterest, a competitor's site, Getty, or an unlicensed source. When in doubt, keep the auto-generated hero. Safe-but-plain beats risky-but-pretty.

## Schema images

Every JSON-LD reference (`BlogPosting.image`, every `ImageObject`) points at `public/og-default.png`, a real 1200x630 PNG, never at the SVG heroes. This is a hard rule (Google Rich Results rejects SVG images in structured data). To regenerate the OG image after a brand change: `node scripts/generate-og-image.cjs`.
